# Contributing for the FDIS Project

Thank you for your interest in being a part of this project!

Please follow the instructions below so that we can maintain a clean workflow.

---

## General Rules
- No sensitive data (.env)
- Keep code clean and readable
- Update documentation if needed
- Follow existing project architecture

---

## Working on code

If you wish to work on a specific part of the project please refer to the CODEOWNERS.md file for the assigned owners and ask for permission before doing so.


Before starting work:
- Check existing issues (if available)
- Or create a new issue describing what you want to work on
- For larger changes, coordinate with other contributors

---

## Code Quality Guidelines

- Follow clean coding practices
- Use meaningful variable and function names
- Avoid unnecessary complexity
- Keep functions small and focused
- Ensure backend follows consistent API structure

---

## Branching 

We use a simple branching strategy:

- `main` → stable version
- `feature branches` → development work (created from `main` for each task or feature)

---

## Merging

Direct merging to the `main` branch is unavailable, in case you wish to merge a `feature` branch with `main` create a `Pull Request` and wait for review and approval from one of the project contributors.

---

## Pull Requests

As mentioned you cannot directly merge code to `main` branch, you have to create a pull request and wait for review and approval.

Making a pull request:
- Create `Pull Request` to `main`
- Describe changes clearly 
- Ensure code works before merging

---

## Commit Messages

Use clear and descriptive commit messages that explain what was changed.

### ✅ Good:
- Add ML pipeline for data processing  
- Add data parsing pipeline for ML model  
- Fix API endpoint response handling  
- Update project documentation  

### ❌ Avoid:
- fix  
- update  
- stuff  
- pipeline  

---
